# Discrepancy and risk register

Disagreements between the pinned design (`ad9386e` since FE-UI-016; earlier entries cite `d23eb85` or `a7e2a63`, [DR-083](#dr-083)), the frontend (base `f1610f0`), the backend capabilities visible through `@template/api-client`, and repository governance (OKF, `docs/architecture`). Screen records in [`screen-inventory.json`](./screen-inventory.json) reference these IDs.

- **Basis:** **F** = confirmed finding (verified in source or design files) · **R** = recommendation · **A** = assumption that needs confirmation.
- **Impact:** High (blocks a screen or risks breaking live behaviour/security) · Medium (visible gap or rework) · Low (cosmetic or easily resolved).
- **Owner:** who must act — Product, Design, Backend, Frontend.

Recommendations here never make the product decision: items needing one are repeated under [Open decisions](#open-decisions).

Password reset (Trello FE-UI-020, design `ad9386e`; [DR-015](#dr-015) details, kept out of the table above to avoid re-aligning it). Backend behaviour verified from `BackendProjectTemplate` source (`PasswordResetsController`, `RequestPasswordResetHandler`, `ResetPasswordHandler`, `TwoFactorOtpService`, `CompletePasswordResetHandler`, rate-limiting configuration):

- Codes are 6 random digits, valid 2 minutes, single-use and discarded after 5 wrong attempts; a request while a code is active sends nothing (no replacement, no re-send). The request response is only a message: no cooldown, retry-at or expiry. Resolution: no countdown (the reference "Resend code in 0:45" is illustrative); resend is always available and its notice says an unexpired code stays valid. The UI states no expiry duration because the contract does not return one.
- Wrong, expired, used and attempt-exhausted codes share one `400` problem without a stable `code`. Resolution: one combined "That code didn't work … wrong, expired or already used" state. The alert's inline "Send a new code" link is omitted: the always-visible "Resend code" control does the same thing, and removing the alert on success would otherwise drop keyboard focus.
- The backend answers an unknown email with `404` on both operations (account enumeration). Resolution: the BFF returns the accepted response for a request and the invalid-code problem for a completion; copy says "If an account uses …" and never claims delivery.
- Completion revokes every session of the account (`RevokeAllAsync`; revoked sessions can no longer refresh and fail the active-session authorization requirement) and returns no tokens. Resolution: the done state says all sessions were signed out; no session or cookie is created. `NotificationType.PasswordResetSuccessful` exists but is never sent, so the UI does not mention a confirmation email.
- Reference password hint "At least 8 characters with a number and a symbol" omits the upper/lower-case rules; the strength bar has no backend rule. Resolution: the full policy hint replaces both.
- Backend/API gaps deferred to BE-DS-006 (https://trello.com/c/s9tsnAcK): no machine-readable code for invalid/expired codes, no cooldown or expiry in the request response, `Retry-After` on `429` is not forwarded by the BFF, the code is consumed before ASP.NET Identity password validation (a policy failure there would need a new code; the client schema mirrors the policy), and the IP-partitioned `PasswordResetPolicy` (5 per 15 minutes, request and completion combined) sees the BFF's address unless forwarded headers are honoured. The BFF's unknown-email mapping is an interim frontend safeguard to revisit under BE-DS-006; no further BFF workarounds are added.

## Final visual, accessibility and responsive QA

Trello FE-UI-016, design `ad9386e`, frontend base `79642f8`. Evidence, coverage and method: [final-visual-qa.md](./final-visual-qa.md) and [final-visual-qa.json](./final-visual-qa.json). IDs start at DR-165. Fixed entries name their regression test.

- <a id="dr-165"></a>**DR-165** (Medium, Design; fixed) — The reference CTA lead (`PublicHome`: `rgba(255,255,255,.85)` 18px on `--brand` `#2563EB`) is 4.19:1, below WCAG AA 4.5:1; `CtaBanner` copied it (`text-on-brand/85`, axe `color-contrast`). Resolution: opaque `text-on-brand` (5.17:1); test `packages/public-ui/src/components/marketing-sections.browser.test.tsx`. Design to update the token use.
- <a id="dr-166"></a>**DR-166** (Low, Design/Backend) — `email-pages/live/*` theme their table wrappers but not `<body>`, so in dark mode a light band shows below a short email (Chromium render, 1440 and 390 wide). Resolution: none in the frontend (emails are backend-owned, BE-DS-008); add a body background to the dark-mode rules when the backend templates are rebuilt.
- <a id="dr-167"></a>**DR-167** (High, Frontend; fixed) — `/forgot-password` (Trello FE-UI-020) was a public path but not an authentication-layout path, so anonymous users saw the signed-in dashboard chrome (sidebar navigation, account menu, Sign out) around the reset form and two `<main>` landmarks. Resolution: `usesDashboardShell` excludes `/forgot-password` like the other anonymous auth pages; tests `apps/user-portal/src/lib/user-layout.test.ts` (every anonymous page gets the auth layout) and `user-layout-shell.test.tsx`. Route, BFF calls and flow states are unchanged.
- <a id="dr-168"></a>**DR-168** (Medium, Frontend; fixed) — On tablet (834 px) the billing history tables widened the page to 921 px: visually hidden copy-button labels in off-screen columns were absolutely positioned relative to an ancestor outside the table's scroll region. Resolution: the `DataTable` scroll region is `relative`; test "keeps visually hidden cell text inside the scroll region" in `packages/ui-core/src/components/table.browser.test.tsx`.
- <a id="dr-169"></a>**DR-169** (Medium, Frontend; fixed) — `ADM-PAYMENT-ANALYTICS` on phones was 492 px wide: the breakdown-table grid had no `min-w-0`, so the tables' intrinsic width sized the whole column instead of scrolling inside their regions. Resolution: `grid min-w-0 grid-cols-1`; test "keeps the phone layout within the viewport" in `payment-analytics-screen.browser.test.tsx`.
- <a id="dr-170"></a>**DR-170** (Medium, Frontend; fixed) — The pricing FAQ (`FaqGrid`) nested `dt`/`dd` two `div`s below the `dl` (axe `definition-list`, `dlitem`; WCAG 1.3.1). Resolution: the card itself is the single `dt`/`dd` group; test in `marketing-sections.browser.test.tsx`.
- <a id="dr-171"></a>**DR-171** (Medium, Frontend; fixed) — The User Portal sidebar help card's support email link was distinguished from the surrounding text by colour only (1.14:1, axe `link-in-text-block`, WCAG 1.4.1) on every signed-in desktop page. Resolution: always underlined; test in `user-layout-shell.test.tsx`.
- <a id="dr-172"></a>**DR-172** (Low, Frontend) — Pages that call `notFound()` during rendering (`/foundations` in production builds, `/billing/purchases/[purchaseId]` with a malformed id) are served as Next's error shell: the custom 404 renders after hydration, so a stored dark theme is applied after first paint. Observed with `next start` (the apps deploy `output: standalone`; confirm there). Resolution: open; consider route-level `not-found.tsx` or validating in `generateMetadata`/middleware.
- <a id="dr-173"></a>**DR-173** (Low, Frontend) — The workbench theme toolbar toggles the `dark` class without `next-themes`, so theme-aware controls in stories (the drawer's Dark mode switch) show the light state in dark captures. Resolution: dark drawer captures are taken in the User Portal; drive `next-themes` from the workbench decorator if dark overlay baselines are needed.

- <a id="dr-174"></a>**DR-174** (Medium, Frontend) — A `DataTable` that scrolls horizontally but has no focusable cells (the `ADM-PAYMENT-ANALYTICS` breakdown tables on phones, after DR-169) is not explicitly keyboard-scrollable (axe `scrollable-region-focusable`, WCAG 2.1.1). Chromium 130+ and Firefox focus such scrollers natively; Safari does not. Resolution: open — give the scroll region `role="region"`, the caption as its name and `tabIndex={0}` (an extra tab stop on every table) or add it only when overflowing (needs client measurement in a server-safe component).
- <a id="dr-175"></a>**DR-175** (Low, Frontend) — On phones the sticky mobile tab bar can cover the lower part of a focused control at the bottom of the first screen (`USR-PURCHASE-DETAIL` "View your subscription", axe `target-size` reports a 15 px visible strip). The page scrolls, and partial obscuring meets WCAG 2.4.11. Resolution: open — `scroll-padding-bottom` equal to the tab bar height in the dashboard shell.

- <a id="dr-176"></a>**DR-176** (Low, Frontend) — The invoice and receipt preview compositions (`USR-INVOICE-DETAIL`, `USR-RECEIPT-DETAIL`, `ADM-INVOICE-DETAIL`) render their loading, error, not-found and unavailable states without a page `h1` (the ready state has one). Preview-only, no route today. Resolution: open — keep the document heading (or a visually hidden one) in non-ready states when the routes are built (DR-160).
