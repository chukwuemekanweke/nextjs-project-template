# Email template catalog

Trello FE-UI-019. [`email-template-catalog.json`](./email-template-catalog.json) is the canonical handoff inventory: subjects, preheaders, triggers, actions, typed variables, security and expiry notes, reference paths and open questions for each template. This page is a short, hand-maintained summary of it. When the two disagree, the JSON wins; update the JSON first, then the matching row here. Architecture, security, client compatibility, password-reset rules and the deferred backend work ([BE-DS-008](https://trello.com/c/RTpBnO3B)) are in [`email-notification-handoff.md`](./email-notification-handoff.md).

The catalog documents designs and proposed content contracts for the backend notification owner. It is not a frontend package or a second notification model: the backend `NotificationType` enum and producer payloads stay authoritative.

## Decisions

Approved decisions are product decisions; their backend implementation is still pending under BE-DS-008. Proposed items need backend review before they are implemented. The JSON `decisions` list is the structured source.

| Decision                      | Outcome                                                                                                                                                                           | Status                           |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| OD-18                         | An in-session password change sends SecuritySettingChanged; PasswordResetSuccessful is only for a completed password reset.                                                       | Approved 2026-11-27              |
| OD-19                         | Password-reset code lifetime changes from 2 to 3 minutes. Current backend behaviour is 2 minutes.                                                                                 | Approved 2026-11-27              |
| OD-20                         | Billing emails (categories subscriptions, invoices, payments, wallet) may be opted out of; security, authentication, account and KYC emails never.                                | Approved 2026-11-27              |
| DR-142                        | The ConfirmEmail subject drops the code ('Your Template confirmation code').                                                                                                      | Approved 2026-11-27              |
| AccountCreated trigger        | AccountCreated is sent on UserEmailConfirmed, not UserCreated.                                                                                                                    | Approved 2026-11-27              |
| AccountCreated checklist      | The three-step checklist is fixed copy in every deployment, not capability-driven.                                                                                                | Approved 2026-11-27              |
| SubscriptionAllocated trigger | SubscriptionAllocated is sent when the allocation becomes active, never when it is only scheduled.                                                                                | Approved 2026-11-27              |
| Receipt type name             | Rename the SubscriptionInvoice enum member to SubscriptionReceipt, keeping value 10, because the template is a receipt; Product delegated the choice, so it needs backend review. | Proposed, pending backend review |

## Per-template contracts

Each entry in the JSON `templates` array holds the design and backend type, sample subject and preheader, category, recipient, proposed trigger, actions, and typed variables (type, required, source, format, sensitivity, missing-data behaviour, backend key or proposed). It also lists security-sensitive content, expiry notes, design content without a backend source, open questions and reference paths. Shared branding variables, formats and recipient rules are top-level JSON fields.
