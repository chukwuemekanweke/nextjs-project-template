# Route mapping

Existing and proposed App Router routes for every logical screen, with application ownership, authentication boundary and implementation status. The per-screen source of truth is [`screen-inventory.json`](./screen-inventory.json) (`route` object); this page is the route-centric view plus the rules that keep boundaries intact.

Routes were read from `apps/*/src/app/**/page.tsx`, each portal's `src/proxy.ts` and `src/config/navigation.ts` at base commit `f1610f0`.

## Rules for every route change

1. **One responsive route per logical screen.** Mobile and dark artboards never become routes; one `page.tsx` renders every viewport and theme.
2. **Business states are not routes.** Billing, KYC, checkout-result and auth states are resolved from backend data inside the page. The only exception is existing behaviour: the checkout return routes (`/billing/checkout/{success,cancelled,return}`) stay because the payment provider redirects to them; the route selects wording only, and the outcome always comes from purchase status.
3. **Guards are additive.** New public pages (`/forgot-password`, `/reset-password`) are added to the explicit `PUBLIC_PATHS` set in `apps/user-portal/src/proxy.ts`. Never widen the proxy matcher or bypass `resolveRouteSession`. New admin routes inherit the admin proxy (`hasRequiredAdminRole`). The backend stays authoritative for every privileged call.
4. **Dialogs and drawers stay on their parent route.** Two-factor setup, wallet top-up, the plan editor and step-up confirmation are overlays. Use a search parameter (`?tab=`, `?edit=`) only where deep-linking is useful, never a parallel route.
5. **No route before its capability.** Screens whose backend does not exist (class D) get no route, navigation item or placeholder page in production; they are previewed through workbench fixtures only (see [integration-strategy.md](./integration-strategy.md#6-fixtures-and-previews)).
6. **Navigation config stays in the app.** `apps/*/src/config/navigation.ts` owns items, groups and visibility; `@template/dashboard-ui` only renders them.

Security (Trello FE-UI-008, roadmap FE-UI-017): `/security` is the only security route. `?tab=overview|password|passkeys|two-factor|sessions|activity` selects the section (absent or unknown values show the overview); `SecurityTabs` derives the active tab from the URL on every render (`useSearchParams`) and replaces the query in place on tab change (`history.replaceState`, no history entry, no server round trip), so links, refresh and shared URLs always match the shown tab. Inactive tabs are unmounted. Two-factor setup, recovery codes, the disable/regenerate proof, passkey naming and every sign-out/removal confirmation remain dialogs on `/security`, never routes.
