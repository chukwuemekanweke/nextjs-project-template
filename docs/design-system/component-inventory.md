# Component inventory

Every reusable pattern found in the reference, the screens that use it, today's closest component, the decision and the owning package. Package responsibilities follow [target-ui-architecture.md §16](./target-ui-architecture.md#16-package-boundaries-target); verdicts on existing code are in [existing-ui-assessment.md](./existing-ui-assessment.md).

Decision vocabulary (from the ticket): **Reuse** unchanged · **Extend** an existing component (REFACTOR) · **New** shared component (INTRODUCE or REPLACE) · **App** keep application-specific · **Deprecate** consolidate or remove in a later ticket.

Reference classes are the CSS classes in the pinned `theme.css` so implementers can open any canonical file and find the pattern.

## 11. Counts

- New shared components: ~45 (`ui-core` ~35, `dashboard-ui` ~9 + charts, `public-ui` ~12, `forms` ~7 fields).
- Extended: ~15. Reused unchanged: `formatMinorUnits`, `Skeleton`, `Breadcrumbs` (restyle only), forms infrastructure.
- Deprecated after migration: `buttonClassName`, `Modal`, `Pagination`, `StatusBadge`, `SectionHeader`, `SettingsRow` (renamed), `ThemeToggle`, `PublicUiProvider`, all Solid sections, collapsed sidebar rail.
